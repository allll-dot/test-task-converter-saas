# Call Statistics

Прототип SaaS-сервиса, который принимает MP3-записи звонков и превращает их в
структурированную аналитику. AI-контур работает локально и не требует платных
API: `faster-whisper` транскрибирует аудио, а Ollama формирует проверяемый JSON.

## Запуск

```bash
docker compose up --build
```

Перед первым анализом загрузите бесплатную локальную модель в Ollama:

```bash
docker compose exec ollama ollama pull qwen3:8b
docker compose exec ollama ollama pull nomic-embed-text
```

Swagger будет доступен по адресу `http://localhost:8000/docs`.

Перед запуском API сервис `migrate` выполняет `alembic upgrade head`. Схема БД
управляется миграциями и не создаётся приложением во время старта.

Для загрузки используется демонстрационный заголовок `X-Organization-ID`.
Это граница tenant в прототипе, а не замена production-аутентификации.

## Разработка

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
alembic upgrade head
pytest
```

Для запуска локальной транскрибации:

```bash
pip install -e '.[local-ai]'
```

Модель Whisper по умолчанию — `small` на CPU с `int8`. Для структурированного
анализа ожидается Ollama с моделью `qwen3:8b`. Названия моделей и адрес Ollama
настраиваются через переменные окружения.

`faster-whisper` не определяет роли участников. До подключения диаризации или
разделения стереоканалов спикер сохраняется как `unknown`, а
`manager_talk_ratio` возвращается как `null`, а не вычисляется из догадки.

После сохранения MP3 API ставит задачу `calls.process` в Redis. Celery-воркер
независимо выполняет транскрибацию, расчёт метрик и структурированный анализ.
Количество воркеров можно увеличивать независимо от API.

Агрегированная статистика доступна через `GET /api/v1/statistics`. Все запросы
считают данные только для организации из заголовка `X-Organization-ID`.

Dashboard доступен по адресу `http://localhost:8000/dashboard`. Для загрузки
данных укажите UUID демонстрационной организации. Экран показывает общее число
звонков, конверсию в запись, среднюю оценку качества, длительность, распределения
исходов и последние обработанные звонки. Данные для таблицы предоставляет
tenant-изолированный `GET /api/v1/dashboard/calls`.

Анализ также определяет исход записи на приём: запись создана, не создана,
перенесена, отменена, неприменима или неизвестна. Дата, время и услуга
сохраняются только при наличии в транскрипте. Dashboard будет показывать
конверсию в запись, распределение исходов, качество звонков и динамику по
периодам; RAG-чат останется дополнительным способом исследовать причины.

## RAG по транскриптам

После основного анализа воркер разбивает транскрипт на фрагменты с таймкодами,
получает бесплатные локальные embeddings через `nomic-embed-text` в Ollama и
сохраняет их в PostgreSQL с расширением `pgvector`. Сбой индексации не отменяет
готовый анализ звонка: dashboard и API результатов продолжают работать.

Задать вопрос по всем звонкам организации или по одному `call_id`:

```http
POST /api/v1/analytics/ask
X-Organization-ID: 00000000-0000-0000-0000-000000000000
Content-Type: application/json

{
  "question": "Какие возражения по стоимости встречались?",
  "call_id": null
}
```

Ответ содержит `sources` с идентификатором звонка, текстом и начальным и
конечным таймкодами. Векторный поиск всегда ограничен `organization_id`.
